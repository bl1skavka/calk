# Об'єднання FuelWise + TimeCalc в один сайт

## Що зроблено

1. Статичний файл `timecalc-main/index.html` скопійовано без змін у
   `public/timecalc.html` — Next.js віддає все з папки `public` як є, тому
   збірка/перезбірка йому не потрібна.
2. Доданий компонент `src/components/SiteSwitcher.tsx`, який підключений у
   `src/app/layout.tsx` і огортає весь застосунок:
   - **FuelWise** (головний застосунок) рендериться завжди, просто
     ховається через `display: none`, коли активний TimeCalc — тому стан
     React (усі введені цифри) ніколи не втрачається.
   - **TimeCalc** живе в постійному `<iframe src="/timecalc.html">`.
     Iframe теж лише ховається, а не перезавантажується — усе, що
     введено на його стороні, теж зберігається.
3. Перемикання:
   - клавіша **F2** — працює будь-де, навіть якщо фокус у полі вводу;
   - кругла кнопка зі стрілками-реверсом у правому нижньому куті екрана —
     зручно для телефону/планшета;
   - вибір сайту запам'ятовується в `localStorage`, тож при наступному
     заході відкриється той сайт, який був активний востаннє.
4. За замовчуванням при першому відкритті сайту показується **FuelWise**.

## Проєкт тепер збирається як звичайний статичний сайт

`next.config.ts` налаштований на `output: 'export'` — команда
`npm run build` більше не запускає внутрішній Node-сервер, а створює
папку **`out/`** зі звичайними `.html`, `.css`, `.js` файлами. Це той
самий "просто HTML", який можна залити куди завгодно, включно з
GitHub Pages, — без Node.js на боці хостингу.

Локально Node.js все одно потрібен один раз — тільки щоб зібрати
проєкт (`npm run build`) і показати готові файли з папки `out/` через
локальний сервер, бо браузери блокують деякі можливості сайту при
відкритті файлів напряму через `file://`.

## Варіант 1 (простіше): запустити локально

1. Один раз встановіть **Node.js** (LTS-версія) з https://nodejs.org.
2. Розпакуйте архів у будь-яку папку.
3. Запустіть відповідний файл подвійним кліком:
   - **Windows** → `start-windows.bat`
   - **macOS** → `start-mac.command` (якщо запитає дозвіл — дозвольте:
     Системні налаштування → Конфіденційність і безпека)
   - **Linux** → `start-linux.sh` (може знадобитись `chmod +x
     start-linux.sh` один раз)
4. При першому запуску потрібен інтернет — скрипт встановить
   залежності і збере проєкт у папку `out/`. Далі браузер сам
   відкриється на `http://localhost:3000`.
5. Щоб зупинити — закрийте вікно консолі.

Якщо міняли код — видаліть папку `out` перед наступним запуском
скрипта, щоб зміни потрапили в збірку.

## Варіант 2: залити на GitHub і відкривати з github.io

Найпростіший спосіб — **GitHub Pages**, з автоматичною збіркою через
GitHub Actions (файл `.github/workflows/deploy.yml` вже готовий і
лежить у проєкті). Вам не треба нічого збирати самому — GitHub сам
запускає `npm install` і `npm run build` на своєму сервері після
кожного push.

Кроки:

1. Зайдіть на https://github.com і натисніть **New repository**.
   Назвіть його як завгодно, наприклад `fuelwise-timecalc`. Публічний
   чи приватний — не важливо (GitHub Pages для приватних репозиторіїв
   доступний, якщо у вас є GitHub Pro/Team/Enterprise; для безкоштовного
   акаунту зробіть репозиторій публічним).
2. Завантажте вміст папки `site/` у цей репозиторій. Найпростіше —
   через веб-інтерфейс: на сторінці порожнього репозиторію натисніть
   **uploading an existing file** і перетягніть туди всі файли й папки
   з `site/` (включно з прихованою папкою `.github/`).
   Або через термінал:
   ```bash
   cd site
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ваш-логін>/<назва-репо>.git
   git push -u origin main
   ```
3. У репозиторії відкрийте **Settings → Pages** і в полі **Source**
   виберіть **GitHub Actions** (не "Deploy from a branch").
4. Зробіть будь-який push (або зайдіть у вкладку **Actions** і
   запустіть workflow "Deploy to GitHub Pages" вручну кнопкою **Run
   workflow**). Збірка займає 1–2 хвилини.
5. Готовий сайт з'явиться за адресою:
   `https://<ваш-логін>.github.io/<назва-репо>/`
   (адресу також показано на сторінці Settings → Pages після
   успішного деплою).

Все налаштовано так, щоб сайт коректно працював саме за такою
адресою з підпапкою (`/<назва-репо>/`) — шлях підставляється
автоматично в `next.config.ts` через змінну середовища
`NEXT_PUBLIC_BASE_PATH`, яку виставляє сам workflow. Якщо захочете
змінити назву репозиторію — нічого вручну підправляти не треба,
наступний push просто пересобере сайт з новим шляхом.

### Примітка

PWA/офлайн-режим (service worker) у цій версії вимкнений — для
статичного експорту він не потрібен, а сайт і так повністю working
online через GitHub Pages.

## Якщо хочете інший файл замість index.html з timecalc

Якщо в архіві timecalc-main є ще й `time.html` або інші сторінки, які
теж потрібні — просто покладіть їх поруч у `public/` і зробіть на них
посилання з `SiteSwitcher.tsx` так само, як зроблено для
`/timecalc.html`.
